# إصلاح 429 عند بدء ربط واتساب — يطبق فوق v2

كان هناك خطأ في إعدادات throttle في الحزمة: مسارات المشترك وإدارة واتساب الجديدة لم تحدد prefix مستقلًا، بينما Laravel 13 يبني المفتاح الافتراضي للمستخدم المسجل على هوية المستخدم دون مسار الصفحة. لذلك كانت طلبات قراءة الحالة التلقائية تستهلك رصيد الربط والفصل، وقد تتداخل مع حدود الطلبات الأخرى.

الإصلاح يضيف مفتاحًا مستقلًا لكل من: قراءة الحالة، بدء الربط، الفصل، وحفظ تذكير المستخدم. تبقى الحدود نفسها: 30/دقيقة للحالة، 5/دقيقة لكل إجراء ربط/فصل، و20/دقيقة لحفظ التذكير. صلاحيات السوبر أدمن وCSRF لم تتغير.

## التركيب

فك محتويات هذا ZIP داخل جذر مشروع Laravel الحالي، ووافق على استبدال الملفين الموجودين:

- `routes/web.php`
- `tests/Feature/WhatsAppSenderAdminTest.php`
- هذا المستند الجديد: `docs/WHATSAPP_429_FIX_AR.md`

ثم نفّذ من جذر المشروع:

```powershell
php artisan route:clear
```

افتح صفحة `/admin/whatsapp` الأساسية من جديد واضغط «بدء الربط» مرة واحدة، وانتظر تحديث الحالة. لا تحدث صفحة `/admin/whatsapp/connect` نفسها لأنها وجهة POST. لا تحتاج إعادة ضبط .env أو الأسرار، ولا migrate أو npm install أو إعادة بناء الواجهة لهذا الإصلاح. اترك خدمة البروفايدر شغالة.

المفاتيح الجديدة مستقلة عن العدادات القديمة؛ لا يلزم مسح cache التطبيق بالكامل. في النشر الذي يستخدم route cache، أعد بناءه بأمر `php artisan route:cache` بعد التركيب. على التشغيل المحلي الحالي يكفي route:clear.

## التحقق

أُعيد إنتاج العطل باختبارين فشلا على v2 قبل الإصلاح، ونجحا بعده:

1. استهلاك حد تحديث الحالة والوصول إلى 429 فيه لا يمنع بدء الربط أو الفصل أو حفظ التذكير.
2. محاولة الربط السادسة خلال دقيقة تظل مرفوضة بـ429، لكنها لا تمنع قراءة الحالة أو الفصل.

اختبارات إدارة واتساب العشرة نجحت (100 assertion)، بما فيها صلاحيات المستخدمين، وحماية QR، وعزل مفاتيح الإدارة. فحص PHP syntax وLaravel Pint للاختبار المعدّل نجحا. لم يُختبر الربط الفعلي برقم واتساب داخل بيئة الفحص.

لا تحتوي الحزمة أسرارًا أو .env أو جلسات أو قاعدة بيانات. لا تغيّر أي ملفات تخص منطق التمارين أو التغذية.
