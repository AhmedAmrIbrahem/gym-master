# تذكير الجيم عبر واتساب — نسخة تجريبية

هذه النسخة تستخدم جلسة WhatsApp Web ذاتية الاستضافة بناءً على طلبك، وليست Cloud API رسميًا. لا تحتاج اشتراك شركة وسيطة أو دفع رسوم API في هذا المسار، لكن تحتاج جهازًا/سيرفر يعمل باستمرار واتصال إنترنت. المكتبة غير رسمية وقد تتوقف الجلسة أو يُحظر الرقم. استخدم رقم تجربة ومستخدمين وافقوا على الاستلام. لم تتغير حسابات التمارين أو التغذية.

## تركيب التحديث

1. خذ نسخة احتياطية من ملفات المشروع وقاعدة البيانات، ثم فك ملفات ZIP **داخل جذر مشروع Laravel** مع الحفاظ على المسارات؛ ليست نسخة مشروع كاملة.
2. استخدم PHP 8.3+ المتوافق مع اعتماديات مشروعك (الاختبار هنا بـ8.5.11)، وNode.js 22+، وnpm. لا توجد اعتماديات Composer جديدة.
3. نفّذ من جذر Laravel:

```powershell
php artisan migrate
php artisan optimize:clear
npm install
npm run build
```

البناء الأخير يضمن تضمين تنسيقات نموذج Blade الجديد في CSS؛ ZIP لا يحتوي vendor أو node_modules أو ملفات build. لا تستخدم migrate:fresh على قاعدة بياناتك.

## تجهيز بروفايدر واتساب

```powershell
cd services/whatsapp-provider
Copy-Item .env.example .env
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
npm install
```

ضع القيمة العشوائية الناتجة في `PROVIDER_TOKEN` بملف `.env` الخاص بالبروفايدر. شغّل أمر توليد السر **مرة ثانية** وضع السر المختلف في `PROVIDER_ADMIN_TOKEN`. كلاهما 32 حرفًا على الأقل، ولا يجوز استخدام نفس القيمة. لا ترسلهما لأحد. اكتب في `PROVIDER_DATA_DIR` مسارًا مطلقًا دائمًا خارج مجلد الموقع العام، مثل `C:/gym-whatsapp-data` على جهازك (أنشئه وأعطِ حساب تشغيل الخدمة حق الكتابة). يحتوي هذا المسار جلسة الحساب وسجل منع التكرار؛ عامله كسر. لا تضعه على تخزين مؤقت ولا ترفعه إلى Git أو النسخ العامة.

```powershell
npm start
```

الخدمة تستمع محليًا دون طباعة QR في الطرفية. أكمل إعداد Laravel أدناه، ثم ادخل بحساب **سوبر أدمن** واختر «رقم إرسال واتساب» من القائمة أو افتح `/admin/whatsapp`. اضغط «بدء الربط / إعادة الاتصال». سيظهر QR في صفحة الإدارة وتتحدث الحالة تلقائيًا كل خمس ثوانٍ. من هاتف رقم الجيم افتح واتساب ← الأجهزة المرتبطة ← ربط جهاز وامسح الرمز. عندما تصبح الحالة «متصل وجاهز» يظهر رقم الحساب المرتبط فعليًا.

رقم الإرسال لا يُحدد بكتابة رقم في نموذج؛ يلزم ربط حساب واتساب الذي تملك هاتفه. لتغييره يفصل السوبر أدمن الرقم الحالي من الصفحة ثم يبدأ ربطًا جديدًا ويمسح QR من الهاتف الجديد. لا يتغير رقم أي مشترك أو موعده عند استبدال رقم الإرسال، ولا يُمسح سجل منع التكرار. يستخدم الجميع رقم إرسال الجيم الواحد، ويصل التذكير لكل مستخدم في محادثته الخاصة، وليست مجموعة. لا يحتاج المستخدمون ربط QR.

صفحة الإدارة وقراءة الحالة/QR والربط والفصل محمية على الخادم بـauth وactive_account وsuper_admin، وطلبات التغيير عبر POST مع CSRF وحد للمحاولات. المشترك ممنوع حتى لو عرف المسار أو أرسل الطلب يدويًا. مفاتيح الخدمة لا تُرسل للمتصفح، واستجابات QR والحالة لا تُخزن في cache. QR يبقى في ذاكرة البروفايدر مؤقتًا ولا يُطبع أو يُحفظ على القرص؛ لا تشارك صورته. مفتاح الإرسال لا يستطيع إدارة الجلسة؛ الإدارة تستخدم سرها المنفصل.

التثبيت ينزّل Chromium بواسطة Puppeteer. إذا تعذر تنزيله، وفّر Chrome مدعومًا واضبط `CHROME_EXECUTABLE_PATH` في إعدادات البروفايدر وفق إعداد Puppeteer. على Linux ثبّت مكتبات Chromium المطلوبة وشغّل الخدمة بحساب عادي. إعداداتنا لا تعطل browser sandbox.

أبقِ `PROVIDER_HOST=127.0.0.1`. لا تعرض المنفذ 3100 للإنترنت. عند فصل الخدمة على خادم آخر استخدم شبكة خاصة مع TLS وجدار ناري، وحدّث عنوان Laravel. اجعل Apache/Nginx يخدم مجلد Laravel `public` فقط؛ لا تعرض جذر المشروع أو `services` أو ملفات `.env`.

## إعداد Laravel

أضف محليًا إلى `.env` الموجود لديك، دون نسخه إلى ZIP:

```dotenv
GYM_REMINDERS_ENABLED=true
GYM_WHATSAPP_URL=http://127.0.0.1:3100
GYM_WHATSAPP_TOKEN=PUT_THE_SAME_RANDOM_PROVIDER_TOKEN_HERE
GYM_WHATSAPP_ADMIN_TOKEN=PUT_THE_DIFFERENT_RANDOM_ADMIN_TOKEN_HERE
GYM_WHATSAPP_EGYPT_LOCAL=true
QUEUE_CONNECTION=database
CACHE_STORE=database
```

استبدل القيم التوضيحية: GYM_WHATSAPP_TOKEN يطابق PROVIDER_TOKEN، وGYM_WHATSAPP_ADMIN_TOKEN يطابق PROVIDER_ADMIN_TOKEN. عند التحديث من الحزمة السابقة أضف مفتاح الإدارة في الطرفين وشغّل `npm install` في مجلد البروفايدر مجددًا لتثبيت qrcode، ثم أعد تشغيل الخدمة. هذه الحزمة كاملة بالنسبة للتغييرات على ZIP المشروع الأصلي، وتغني عن الحزمة السابقة.

تستخدم الجداول jobs وfailed_jobs وcache وcache_locks من migrations المشروع الحالية. لا تستخدم `QUEUE_CONNECTION=sync` عند التشغيل الدائم. بعد تغيير الإعدادات:

```powershell
php artisan optimize:clear
php artisan queue:restart
php artisan queue:work --queue=gym-reminders --tries=1 --timeout=60 --sleep=2
```

في طرفية مستقلة شغّل المجدول محليًا:

```powershell
php artisan schedule:work
```

على السيرفر استخدم cron كل دقيقة بدل schedule:work:

```cron
* * * * * cd /absolute/path/to/gym-dashboard && php artisan schedule:run >> /dev/null 2>&1
```

على Windows يمكن استخدام Task Scheduler كل دقيقة لتشغيل `php.exe` بالوسيط `artisan schedule:run` مع ضبط Start in إلى جذر Laravel. شغّل البروفايدر وعامل الطابور كخدمات تحت مراقب عمليات. `retry_after` لاتصال الطابور يجب أن يكون أكبر من 60 ثانية؛ الافتراضي في المشروع 90 ثانية. خدمة البروفايدر متسلسلة الإرسال، فتعود الطلبات المتزامنة غير المقبولة إلى المحاولة في الدقيقة التالية. هذه نسخة تجربة وليست بنية مهيأة للأعداد الكبيرة.

## تجربة المستخدم

من الملف الشخصي يظهر قسم «تذكير موعد الجيم على واتساب». يختار المستخدم وقت التذكير والمنطقة الزمنية ويوافق صراحة على استقبال الرسالة ثم يحفظ. التذكير يومي؛ لا يقرأ جدول التمارين أو يغيره، ولا يستنتج أيام الراحة. الرقم من الحساب فقط، ولا يمكن تمرير رقم بديل أو user_id عبر النموذج. إذا كان الرقم ناقصًا تطلب الصفحة تحديثه من إدارة الحسابات الموجودة.

الأرقام الدولية تستخدم `+` وكود الدولة، ويمكن استخدام `00` بدل `+`. عند تفعيل دعم مصر تتحول أرقام المحمول المصرية مثل `01012345678` إلى `+201012345678`. لا نفترض دولة للأرقام المحلية الأخرى. تغيير رقم الحساب يوقف صلاحية الموافقة القديمة عند التنفيذ، حتى يراجع المستخدم إعداداته ويوافق مجددًا. حساب معطل أو تذكير متوقف أو موافقة مسحوبة لا يُرسل له عمل جديد. الإيقاف لا يسترجع رسالة بدأت عملية إرسالها بالفعل.

أوقف التذكير بإلغاء علامة التفعيل وحفظ الإعدادات، دون الحاجة للموافقة. مفتاح `GYM_REMINDERS_ENABLED=false` يوقف الإرسال كله؛ بعدها أعد تحميل إعدادات Laravel وعامل الطابور. الإعدادات محفوظة حتى لو الخدمة متوقفة.

## التوقيت ومنع التكرار والتعافي

- المجدول يعمل كل دقيقة ويقبل التأخر حتى 10 دقائق فقط. إذا كان الموقع أو العامل متوقفًا أطول من ذلك، يُتخطى التذكير القديم بدل إرساله في موعد غير مناسب. يستمر اليوم التالي طبيعيًا.
- تذكير واحد كحد أقصى لكل مستخدم/تاريخ محلي. قاعدة البيانات تفرض قيدًا فريدًا، والعامل يحجز سجل الإرسال قبل الاتصال. تكرار schedule:run أو تكرار وصول نفس المهمة لا يكرر الإرسال.
- `scheduled_at` محفوظ UTC صراحة حتى مع كون منطقة التطبيق Africa/Cairo. اختيار المستخدم للمنطقة مستقل. وقت غير موجود عند بداية التوقيت الصيفي يُرحّل حسب قواعد PHP للوقت الصحيح التالي؛ الساعة المكررة عند نهاية التوقيت الصيفي لا تنتج إرسالين.
- كل تعديل للإعدادات يغيّر version؛ عمل الطابور للإعداد السابق يُتخطى. إذا كان سجل اليوم قد أُنشئ بالفعل، فلن ننشئ تذكيرًا ثانيًا للتاريخ نفسه بعد تعديل الإعدادات، حتى لو لم يُرسل الأول.
- سجل البروفايدر يحفظ المفتاح وبصمة الطلب وحالته على القرص، لا نص الرسالة أو رقم المستلم. إعادة نفس المفتاح المكتمل تعيد النتيجة دون إرسال جديد، واستخدامه لطلب مختلف يُرفض.
- إذا صرّح البروفايدر بأنه `not_ready` **قبل قبول الإرسال**، تُعاد المحاولة عبر outbox في الدقيقة التالية خلال مهلة الموعد. فشل HTTP أو timeout بعد قبول محتمل يُصنّف `unknown` ولا يُعاد تلقائيًا. هذا تفضيل لمنع التكرار على ضمان وصول كل تذكير؛ لا ندّعي exactly-once أو ضمان التسليم من واتساب.
- `sent` تعني أن مكتبة واتساب أعادت نتيجة إرسال، وليست إثبات وصول أو قراءة على هاتف المستخدم. لا يوجد webhook لتأكيد التسليم في هذه النسخة.

حالات جدول `gym_reminder_deliveries`: `pending` انتظار، `sending` محجوز قيد التنفيذ، `sent` أعاد البروفايدر نجاحًا، `skipped` انتهت المهلة أو تغيرت الشروط، `failed` إعداد أو مستلم غير صالح، `unknown` نتيجة غير مؤكدة. إذا مات العامل بعد الحجز، يبقى `sending` للمراجعة ولا يُعاد إرسال نفس اليوم تلقائيًا. راجع السجلات عبر أداة قاعدة البيانات الإدارية؛ لا تعرضها للمستخدمين الآخرين. لا تغير unknown/sending إلى pending عشوائيًا، ولا تمسح ledger لتجربة الإرسال مجددًا.

شغّل نسخة واحدة فقط من البروفايدر لكل جلسة/مجلد بيانات. عند إيقاف نظيف يُحذف `provider.lock`. بعد انهيار العملية: تأكد أن العملية القديمة وChromium الخاص بها توقفا بالكامل، ثم احذف **ملف provider.lock وحده** وأعد التشغيل. احتفظ بـauth وledger. عند إعادة تشغيل الخدمة تُستعاد الجلسة المحفوظة تلقائيًا؛ الربط الأول يبدأ من السوبر أدمن. إذا خرجت الجلسة استخدم «إعادة الاتصال» في صفحة الإدارة وامسح QR عند ظهوره. لا تحذف بيانات جلسة أخرى ولا تشغّل عمليتين على نفس مجلد البيانات.

يرفض البروفايدر فصل أو استبدال الرقم أثناء إرسال جارٍ أو عملية شبكة لم تنتهِ فعليًا حتى لو انتهت مهلة HTTP، ويرفض الفصل أثناء بدء Chromium. انتظر ثم حدّث الحالة. إذا علقت العملية، راجع المشغّل وأوقف خدمة البروفايدر ومتصفحها بالكامل قبل إعادة التشغيل. لا تُعرض الجلسة جاهزة بعد فشل الفصل، ولا يعاد إرسال النتيجة غير المؤكدة تلقائيًا.

## فحص التشغيل

1. شغّل البروفايدر، العامل والمجدول. اربط رقم الإرسال من صفحة السوبر أدمن وتحقق من ظهور رقمه وحالة الاتصال. حدّد لمستخدم تجريبي موافق موعدًا بعد دقيقتين ومنطقة زمنية صحيحة ورقمًا تملكه.
2. عند الموعد افحص وصول الرسالة الخاصة، وحالة سجل اليوم. أعد تشغيل `php artisan gym-reminders:dispatch` مرتين؛ يجب ألا تصل رسالة إضافية.
3. اختبر مستخدمًا آخر برقم مختلف، ثم إيقاف التذكير، ثم تغيير الرقم قبل تنفيذ مهمة في الطابور. تحقق أن الرسالة لا تصل للرقم الجديد دون موافقة.
4. جرّب حساب مشترك؛ يجب ألا يرى رابط إدارة الرقم، وأن يُرفض GET/POST إلى مسارات `/admin/whatsapp` المباشرة. من السوبر أدمن افصل رقم الإرسال ثم اربط رقم تجربة آخر وتحقق أن الرقم المعروض تغيّر وبقيت إعدادات المشتركين محفوظة.
5. أوقف البروفايدر أو افصل الجلسة؛ راقب أن النتيجة لا تسبب إعادة إرسال غير مؤكدة، ثم أعد ربطه للتذكيرات اللاحقة.

الاختبارات الآلية لا تتصل بواتساب ولا تحتاج رقمًا حقيقيًا:

```powershell
php artisan test --filter=GymReminderTest
php artisan test --filter=WhatsAppSenderAdminTest
php artisan test
cd services/whatsapp-provider
npm test
```

## الانتقال إلى المسار الرسمي

العامل يعتمد على واجهة `App\Services\GymReminders\WhatsAppSender`، والبروفايدر التجريبي مربوط بها في AppServiceProvider. لاحقًا أضف implementation لـCloud API يستخدم رقم الأعمال وقالبًا معتمدًا وإعدادات Meta، واستبدل binding بعد الاختبار. لا يكفي تغيير URL إلى Meta: صيغة الطلب والقالب والتعامل مع النتائج مختلفة. لا يوجد Cloud API جاهز أو قالب معتمد داخل هذا التسليم؛ نطاقه النسخة التجريبية التي وافقت عليها.

المراجع: [whatsapp-web.js](https://github.com/wwebjs/whatsapp-web.js)، [LocalAuth](https://wwebjs.dev/guide/creating-your-bot/authentication.html)، [Client API](https://docs.wwebjs.dev/Client.html)، [إرشادات واتساب](https://www.whatsapp.com/legal/messaging-guidelines).
