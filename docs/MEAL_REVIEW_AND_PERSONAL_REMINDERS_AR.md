# تحديث مراجعة وجبة الصورة والتذكيرات الشخصية

التحديث مبني على `gym-dashboard (2).zip` ويشمل تحسينات حقل الشات السابقة. يحتوي ZIP على الملفات المعدلة والجديدة فقط بمساراتها داخل جذر Laravel، ولا يحتوي `.env` أو أسرارًا أو vendor أو node_modules.

## التركيب

1. خذ نسخة احتياطية من قاعدة البيانات وملفات المشروع. أوقف نافذتي `schedule:work` و`queue:work` مؤقتًا بـCtrl+C حتى لا يعمل كود قديم أثناء تحديث الجداول.
2. فك ZIP داخل `gym-dashboard` مع استبدال الملفات والحفاظ على المسارات.
3. من جذر المشروع شغّل:

```powershell
php artisan migrate
php artisan optimize:clear
php artisan queue:restart
```

4. شغّل العامل والمجدول في نافذتين منفصلتين:

```powershell
php artisan queue:work --queue=gym-reminders --tries=1 --timeout=60 --sleep=2
```

```powershell
php artisan schedule:work
```

خدمة واتساب الحالية `npm start` تظل مطلوبة، ولا يتغير البروفايدر بهذا التحديث. حدّث الصفحة أو أغلق تبويب الهاتف وافتحه لتجنب نموذج قديم. لا توجد حزم جديدة أو حاجة إلى npm build. لا توجد متغيرات بيئة جديدة: يُستخدم مفتاح Gemini وموديلاته وإعدادات واتساب الموجودة. موديل Gemini يجب أن يدعم الصور وJSON Structured Output. راجع [مرجع Google الرسمي](https://ai.google.dev/gemini-api/docs/structured-output)؛ القيم الغذائية الناتجة تقديرات وليست قياسات مؤكدة.

## سيناريو الأكل

- أرسل صورة الأكل، ومعها الوزن وطريقة الطبخ إذا كنت تعرفهما. المسموح JPG/PNG/WebP حتى 5 MiB وأبعاد 10000×10000 كحد أقصى.
- يظهر تقدير الأصناف والكميات والسعرات والبروتين والكربوهيدرات والدهون، ومعه «راجع واحفظ الوجبة». لا توجد إضافة تلقائية لسجل التغذية.
- اضغط الزر لمراجعة الاسم والوزن والقيم لكل كمية معروضة، واختيار اليوم ونوع الوجبة. الأيام المسموحة من 2000 وحتى اليوم بتوقيت القاهرة.
- تغيير الوزن يعدّل قيم الصنف نسبيًا من القيم المعروضة، ويمكن تعديل كل قيمة يدويًا أو حذف صنف. يوجد إجمالي مباشر قبل التأكيد.
- عند «تأكيد حفظ الوجبة» تضاف الأصناف إلى وجبة المستخدم نفسه. تظهر في إجماليات التغذية والتاريخ بالطريقة الحالية، مع زر لفتح سجل اليوم.
- الضغط المتكرر أو إعادة نفس الطلب بعد انقطاع الاتصال لا يكرر التسجيل. إعادة نفس معرف المراجعة بقيم مختلفة بعد الحفظ تُرفض بدل إنشاء وجبة أخرى.

تُحوّل قيم الكمية التي راجعها المستخدم إلى قيم لكل 100 جم وفق نموذج Food الحالي، وتُربط من خلال AddMealItemAction الموجود. تُنشأ أصناف خاصة بالمستخدم أو يُعاد استخدام صنف مطابق تمامًا في بنك طعامه؛ لا تُعدّل أصناف عامة أو قيم وجبات سابقة. قد يظهر فارق تقريب صغير لأن حسابات السجل الحالية تقرّب القيم. الحسابات الأصلية وواجهات التمارين لم تتغير.

يُقبل حتى 12 صنفًا في المراجعة. لا يظهر زر الحفظ عند رد AI غير صالح أو عدم وجود أكل واضح، ولا يُتاح حفظ وجبات شخصية للسوبر أدمن. كل معرف مراجعة مرتبط بصاحبه، مع التحقق من تسجيل الدخول والحساب النشط وCSRF. لا يمكن تمرير معرف مستخدم أو وجبة أو صنف لتجاوز العزل.

الصورة نفسها لا تُحفظ في public/storage أو قاعدة البيانات، ولا تُرسل معها بيانات الحساب أو سجل المحادثة. التقدير النصي المنظم يُحفظ كمسودة خاصة قابلة للمراجعة لمدة 24 ساعة؛ بعد ذلك يلزم رفع الصورة من جديد. تحتفظ المسودة بعلامة الحفظ لمنع التكرار، ويُحذف سجل المسودة بعد مرور 7 أيام على انتهاء صلاحيته بواسطة مهمة يومية الساعة 03:30 بتوقيت القاهرة. حذف المسودة لا يحذف الوجبات المسجلة، والمعرف المحذوف لا يقبل الحفظ مرة أخرى. تنطبق سياسات Gemini على الصورة والوصف المرسلين إليه.

## سيناريو التذكيرات

المستخدم يحدد أيام الجيم وموعد كل يوم، ثم يختار من تذكير واحد إلى 3 تذكيرات تطبق على الأيام المختارة. كل تذكير عدد دقائق قبل الجيم: من 0 حتى 1440 دقيقة (24 ساعة)، دون تكرار نفس المدة. 0 يعني وقت موعد الجيم. إيقاف التفعيل يوقف جميع التذكيرات ويُبطل الموافقة القديمة؛ التفعيل والتعديل يحتاجان تحديد خانة الموافقة.

مثال: الجيم الساعة 17:00، والتذكيرات 60 و15 و0 ← الإرسال الساعة 16:00 و16:45 و17:00. موعد الاثنين 00:15 والتذكير قبله بـ30 دقيقة ← الإرسال الأحد 23:45، ويُحسب التذكير ضمن يوم جيم الاثنين حتى لو كان الأحد يوم راحة.

- الإعداد الافتراضي للمستخدم الجديد من الواجهة: تذكير واحد قبل الجيم بـ30 دقيقة.
- الاشتراكات القديمة تُرحّل إلى تذكير واحد عند الموعد نفسه `[0]`، مع الحفاظ على أوقاتها وموافقتها وسجل الإرسال. ليست هناك رسائل مبكرة إضافية بمجرد الترقية.
- المدد تُحسب بالدقائق الفعلية عبر UTC، مع اختيار مواعيد الجيم بتوقيت Africa/Cairo ومراعاة التوقيت الصيفي. لو وقع موعد الجيم داخل ساعة محذوفة عند بدء التوقيت الصيفي، يُتخطى هذا الموعد لذلك اليوم بدل تغيير الوقت المختار تلقائيًا. الساعة المتكررة عند انتهاء الصيفي لا تولّد تذكيرًا مكررًا.
- بعد الحفظ تُرسل فقط التذكيرات التي لم يمر وقتها. توجد مهلة تأخير تشغيل قدرها 10 دقائق وفق الإعداد الحالي؛ انقطاع المجدول فترة أطول لا ينتج دفعة رسائل قديمة.
- الحفظ بلا تغيير أو تغيير ترتيب المدد لا يعيد الإرسال. نفس موعد الجيم ونفس مدة التقديم لا يُعاد إرسالهما بعد تعديل إعدادات أخرى. تعديل موعد الجيم لاحقًا قد يستخدم الفرص المتبقية، لكنه لا يفتح 3 فرص جديدة كل مرة.
- الحد الأقصى 3 سجلات إرسال محجوزة/مرسلة/فاشلة أو مجهولة لكل مستخدم وتاريخ جيم، عبر جميع تعديلات الإعدادات. الرسائل المجهولة لا تُعاد تلقائيًا. السجلات الملغاة قبل الإرسال لا تستهلك فرصة. يُفرض الحد بالخادم وقفل حساب المستخدم ومعرف فريد للتذكير، وليس بزر الواجهة فقط.
- رقم الاستقبال من الحساب فقط. تغيير الرقم يبطل الموافقة السابقة. السوبر أدمن يتحكم في رقم الإرسال ونص الرسالة، والمشترك لا يمكنه تعديلهما.

متغيرات نص الأدمن: `{name}` الاسم، `{time}` **موعد الجيم**، `{day}` يوم الجيم، `{date}` تاريخ الجيم، `{timezone}` القاهرة، `{minutes_before}` عدد الدقائق قبل الجيم (0 عند الموعد). النص يثبت عند أول محاولة إرسال لنفس السجل حتى لا يتغير مع مفتاح إعادة المحاولة.

## الشكل والتحقق

الحقول بعرض مرن، وأزرار مناسبة للمس، وحجم خط 16px في الحقول، مع تقسيم حقول الماكروز إلى أعمدة حسب المساحة. يوجد دعم للوضع الفاتح والداكن وRTL ومساحة الهاتف الآمنة، وضبط ارتفاع الشات عند ظهور لوحة المفاتيح عبر VisualViewport عند توفره. هذه واجهات ويب متجاوبة؛ لا تُنشئ تطبيقات iOS أو Android منفصلة.

```powershell
php artisan test --filter=FoodPhotoMealReviewTest
php artisan test --filter=ChatbotFoodPhotoTest
php artisan test --filter=PersonalReminderOffsetsTest
php artisan test --filter=PersonalReminderMigrationTest
node --test tests/Frontend/chatbot-food-photo.test.cjs
```

تشمل الاختبارات العزل، ومنع التكرار، وحسابات السجل بعد الحفظ، والتراجع الكامل عند فشل الحفظ، وانتهاء المسودة وتنظيفها، ورفض مخرجات Gemini غير الصالحة، والتذكيرات الثلاثة، وحد التعديل، ومنتصف الليل والتوقيت الصيفي، وعدم الإرسال المبكر، وترحيل التاريخ القديم. اختبارات Gemini وواتساب تستخدم بدائل وهمية ولا ترسل صورًا أو رسائل حقيقية. تعذر تشغيل متصفح الفحص البصري داخل بيئة التنفيذ؛ يُنصح بمراجعة الشكل بعد الدمج على الأجهزة الفعلية.

الترحيل الجديد يحافظ على سجل الرسائل. إذا أصبحت هناك عدة تذكيرات لنفس اليوم والإصدار، يرفض rollback الخاص به استعادة القيد القديم حتى تتم تسوية/تصدير التاريخ؛ لا يحذف بيانات الإرسال لإجبار الرجوع.
